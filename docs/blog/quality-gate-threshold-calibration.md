# 抄来的画质门控阈值，在我的模型上全是错的

> 上篇文章讲了我把 ArcFace 相似度阈值从抄来的 0.8 改成实测标定的 0.45。
> 这篇讲第二件事：**画质门控的阈值同样抄不了**——
> 而且抄错的程度比相似度阈值离谱得多：不是"查不出问题"，而是**把好照片全拒了**。

---

## 一、为什么要在录入口加门控

人脸录入的流程天然是"来者不拒"：前端拍一张，后端检测到脸，存盘、入库、写向量。
看起来很顺，但有个致命问题——

**录进去一张糊图，后续识别天天失败，而且失败时无法回溯原因。**

库里只存了一张 `1789xxxxx.jpg`，谁知道当时拍成什么样？
等考勤的时候发现"这张脸识别不出来"，已经晚了：
不知道是当时拍糊了、拍歪了、还是现在这个人变了样。

所以我想在**检测之后、入库之前**加一道门控，把脏数据挡在入口。
规则本身不难想到：脸别太小、画面别有别人、别歪头、光线要够、别太糊。

真正麻烦的是——**阈值怎么定。**

## 二、参考实现给了 5 条规则和 6 个阈值，我一个都没法直接用

手上有份参考实现（老师给的），`core/quality_gate.py`，规则写得很完整：

```python
QUALITY_MIN_FACE_WIDTH = 80
QUALITY_MIN_FACE_HEIGHT = 80
QUALITY_MIN_SHARPNESS = 15.0
QUALITY_MIN_BRIGHTNESS = 55.0
QUALITY_MAX_BRIGHTNESS = 215.0
QUALITY_MAX_ROLL_ANGLE = 20.0
QUALITY_MAX_NOSE_OFFSET_RATIO = 0.2
```

看起来直接抄就行。但我用的检测模型**和它不是同一个**：
参考实现用 OpenCV YuNet，我用 insightface 的 SCRFD + ArcFace。

我以为"人脸检测"这件事大家都是一样的，抄阈值只是抄个数字。
**我错了。**

---

## 三、第一个坑：五点顺序反了，倾角算出来是 150~180 度

参考实现的侧倾检测是这样的：

```python
left_eye = face.left_eye
right_eye = face.right_eye
dx = float(left_eye[0] - right_eye[0])
dy = float(left_eye[1] - right_eye[1])
if abs(dx) < 1e-6:
    return 90.0
return abs(math.degrees(math.atan2(dy, dx)))
```

YuNet 的五点顺序是 `[右眼, 左眼, 鼻尖, 右嘴角, 左嘴角]`，
而 insightface 是 `[左眼, 右眼, 鼻尖, 左嘴角, 右嘴角]`——
**前两个反过来了**。

后果：`dx` 是负数，`atan2(dy, dx)` 落进第二象限，算出来全是 150~180°。
我自己的 12 张正常样本，每个都会被判成"严重侧脸"。

```
文件                参考公式算出    修正后
alpha__1.jpg           152.7°        27.3°
bravo__1.jpg           163.7°        16.3°
golf__1.jpg            175.4°         4.6°
```

**修正办法**：用 `abs(dx)` 构角，而不是直接 `atan2(dy, dx)`：

```python
dx = abs(float(le[0] - re[0]))
dy = abs(float(le[1] - re[1]))
return abs(math.degrees(math.atan2(dy, dx)))
```

顺带解决了一个我原本没想到的问题：**前端摄像头是镜像的**。
用绝对值构角之后，镜像与否完全不影响判定，这条规则对镜像天然免疫。

## 四、第二个坑：检测置信度对画质根本不单调

参考实现有条规则是"检测置信度 ≥ 0.85"。我照抄了，然后发现自己的样本大面积不过。

于是我去量了一下这个指标到底怎么变——把同一批图加高斯模糊，再测一次：

```
样本            原始 score    加模糊后 score
alpha__1.jpg       0.612          0.774
bravo__1.jpg       0.904          0.898
delta__1.jpg       0.882          0.849
```

**加了模糊，置信度反而升高了。**

原因是 insightface 的 `det_score` 是 SCRFD 检测头的输出，
它衡量的是"检测器多确信这里有张脸"，而不是"这张脸拍得好不好"。
画面糊了之后，检测器反而更容易框出一个"大致是人脸"的区域。

所以这个指标**不能当画质指标用**，只能当"检测器有没有认出来"的下限。
我把阈值从 0.85 降到 0.50，理由写进代码注释：

```python
MIN_DET_SCORE = 0.50   # 正常样本最小 0.612
# 不能照抄 YuNet 的 0.85 —— insightface 的 det_score 随画质非单调，
# 实测加模糊后反而升高，只能当下限用
```

## 五、第三个坑：画面里有几张脸，不能当"多人"判据

参考实现有个 `check_face_count`：`len(faces) >= 2` 就拒。

我照抄后第一轮跑，**12 张合格样本里有 2 张被拒**。

原因很朴素：我这批样本是从一张 6 人合影里裁出来的，
裁的时候难免带进背景里另一个人的脸。检测器扫到 2 张脸 —— 但：

```
alpha__3.jpg   检出 2 张，第二张面积只有主脸的 8.4%
alpha__4.jpg   检出 2 张，第二张面积只有主脸的 17.1%
```

这显然不是"画面里有两个人"，这是"背景带了个路人"。

改成**面积比**判据就对了：

```python
MULTI_FACE_AREA_RATIO = 0.30   # 第二张脸面积 ≥ 主脸 30% 才算多人
```

实测：并排两人（真多人）面积比 0.90~1.00 → 拦住；
背景小脸面积比 0.08~0.17 → 放行。

## 六、最有意思的一个发现：过曝不能用亮度均值判

规则写完后我开始造测试数据。本机 12 张真实人脸当"合格样本"，
然后人工退化出"不合格样本"：加模糊、压暗、提亮、缩小、旋转、拼多人。

跑第一轮，**过曝这一类漏放了一张**。

我第一反应是阈值算错了，调了一下没用。于是回头看数据：

```
             平均亮度    纯白像素占比
正常样本        96~173        0.0%~6.3%
过曝样本      193~252       40.3%~89.7%
```

问题就在这：**亮度均值从 96 涨到 193，涨了 2 倍，看起来"有点亮"而已。**
但纯白像素占比从 0% 跳到 40% —— 细节已经被烧成纯白，**不可逆地丢了**。

这两个数字描述的是两种完全不同的情况：

- 均值升高：画面整体偏亮，**可能还保留着细节**（比如人脸本来就白、背景亮）
- 纯白占比升高：像素已经**顶到 255，信息真的没了**

所以过曝必须用饱和像素占比判：

```python
MAX_SATURATION_RATIO = 0.25   # 正常样本最大 6.3%，过曝样本最小 40.3%

@classmethod
def saturation_ratio(cls, image, face):
    """人脸 ROI 中接近纯白（灰度 ≥ 250）的像素占比。"""
    roi = cls.normalized_roi(image, face)
    gray = cv2.cvtColor(roi, cv2.COLOR_BGR2GRAY)
    return float(np.mean(gray >= 250))
```

改完之后过曝类 12/12 全拦。

**这条是我原本想不到的**——不是抄来的，也不是推出来的，
是被"漏放了一张"逼出来回头看数据才发现的。

## 七、还有个顺序问题：亮度必须排在清晰度前面

参考实现的注释里写了这个经验，我一开始没当回事：

> 如果先报"画面模糊"，用户会去"稳住摄像头"，永远解决不了问题。

实测数据支持这个说法。压暗到 18% 的样本，清晰度指标同时塌到 4.7（远低于阈值 25）。
如果先跑清晰度规则，用户收到的提示是：

> 画面模糊（清晰度 5），请稳住摄像头或擦净镜头

用户会以为摄像头脏了，反复擦镜头——但真正的原因是**没开灯**。
正确的提示应该是：

> 光照不足（亮度 18，下限 55），请开灯或靠近光源

所以规则顺序是：**尺寸 → 多人 → 置信度 → 侧倾 → 姿态 → 亮度 → 清晰度**，
亮度在清晰度前面。

单元测试里我专门加了一条断言锁死这个顺序：

```python
def test_规则顺序():
    """亮度规则必须在清晰度规则之前 —— 否则用户会去擦镜头而不是开灯。"""
    dark = make_dark_image()
    result = quality_gate.check(dark, face)
    assert result.rule == "G6"   # 不能是 G7
```

## 八、最后的标定结果

写了 `scripts/calibrate_quality.py`，可复现：

```bash
.venv/Scripts/python.exe scripts/calibrate_quality.py
```

拿 12 张真实人脸 + 8 类人工退化，逐项量分布，
取「合格样本最劣值」和「退化样本最优值」之间当阈值：

```
阈值                        合格侧      退化侧   判定
MIN_FACE_WIDTH              94.702     78.719   OK
MIN_FACE_HEIGHT            121.510    101.025   OK
MIN_SHARPNESS               36.326     14.875   OK
MIN_BRIGHTNESS              96.445     16.876   OK
MAX_BRIGHTNESS             173.196    252.200   OK
MAX_SATURATION_RATIO         0.063      0.897   OK
MAX_ROLL_ANGLE              30.766     88.287   OK
MAX_NOSE_OFFSET_RATIO        0.216      0.266   OK
MIN_DET_SCORE                0.612      0.515   OK

合格样本：通过 12 / 误伤 0
blur / blur_heavy / dark / overexpose / small / side / multi  → 各 12/12 全拦
bg_face（背景小脸）→ 放行 12 / 误拦 0
```

注意 `bg_face` 这一行 —— 它专门用来验证**不误伤**。
只报"拦住了多少"是不够的，阈值太松的话正常数据也会被拦，
所以必须有一类"看着像问题但其实合法"的样本，
用来证明你的规则不是宁可错杀。

另外坦白一点：**阈值取在"合格侧最劣值"旁边，也就是贴着合格样本的上限。**
这意味着我的样本本身如果有偏（都是同一个人、都是室内光），
阈值就偏了。12 张样本是"本机素材上的正确性验证"，
不是通用人脸数据集上的基准 —— 面试时我会这么讲。

## 九、清单

**可以照抄的**：规则**顺序**（亮度在清晰度之前）、ROI 归一化的必要性、
拒绝时给可执行提示而不是"图片不合格"。

**不能照抄的**：任何具体数值、任何依赖关键点顺序或检测器输出的公式。

**最值得记住的一条**：
> 阈值不是一个"设一次就不用管"的参数，
> 它是**你的数据分布**的函数。换了模型、换了摄像头、换了光照环境，
> 都得重新量一遍。
>
> 而量出来的第一件事，是看看你抄来的那个数到底离谱到什么程度。
