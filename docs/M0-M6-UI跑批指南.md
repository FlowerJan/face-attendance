# M0 → M6 UI 全流程跑批指南

> **面向**：项目作者本人，用浏览器把六个里程碑在**界面**点一遍。
> **配套**：`docs/ui-run-materials/` 里的照片素材（已实测过每张的实际行为）。
> **配套**：`backend/scripts/run_all_m0_m6.py` 是命令行版的全链路跑批（不需要浏览器时用）。

---

## 第 0 步：开两个 cmd 窗口

**窗口 A（后端）**：

```bat
cd /d E:\your\path\to\face-attendance
scripts\start-backend.cmd
```

**窗口 B（前端）**：

```bat
cd /d E:\your\path\to\face-attendance
scripts\start-frontend.cmd
```

然后浏览器打开 **<http://localhost:5173>**。

> ⚠️ **必须用 `localhost`，不要用 `127.0.0.1`** ——
> 本机 vite 只监听 IPv6 的 `[::1]:5173`，用 `127.0.0.1` 访问会返回 502。
> 接口文档在 <http://localhost:8000/docs>。

> ⚠️ **Milvus Lite 是单进程文件锁**：`backend/milvus_lite.db` 只能被一个进程打开。
> 跑 M3 播种前必须**把窗口 A 关掉**，否则报 `DataDirLockedError`。

## 一、页面地图：六个里程碑对应哪个界面

| 里程碑 | 界面 | 路由 | 你要点什么 |
|---|---|---|---|
| **M0** 环境与模型 | — | — | 后端起来即通过（`/api/health` 返回 ok） |
| **M1** 学生管理 | 学生列表 | `/students` | 新增/搜索/编辑/删除学生 |
| **M2** 人脸录入 + 画质门控 | 人脸录入 | `/faces` | 选学生 → 传照片 → 看门控判定 |
| **M3** 签到识别 | 人脸签到 | `/attendance` | 传照片 → 看认出/未认出/歧义 |
| **M4** 统计汇总 | 数据统计 | `/stats` | 看当日签到率与覆盖率 |
| **M5** 脸库审计 | 脸库审计 | `/audit` | 运行审计 → 看疑似重复/脏数据 |
| **M6** 公告与通知 | 公告栏 | `/notices` | 发公告 → 看 WebSocket 实时推送 |

> ⚠️ **注意映射与参考项目不同**：参考项目 pro002 的 M0–M6 是「桌面端 + 双端整合」的工程里程碑；
> 本项目是 Web 成品，**M0–M6 对应的是「业务能力链」**：环境 → 建档 → 录入 → 识别 → 统计 → 审计 → 通知。
> 底层能力（画质门控、阈值标定、诊断字段）在界面上都是**看得见的效果**，不是隐藏的代码。

| 步骤 | 操作 | 预期 |

| 1 | 点「新增学生」 | 弹出表单 |
| 2 | 填学号 `20240999`、姓名 `测试同学`、性别、班级、专业、入学年、手机号 | **班级与专业必须从下拉里选**（字典来自 `backend/data/班级.csv`、`专业.csv`），手打会报「invalid class」 |

### M2 · 人脸录入 `/faces` —— 验证画质门控

这是**脏数据防线**，界面上能直接看到效果。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 搜索框选 `20240001`（alpha，已录 6 张） | 右侧出现「已录入脸照」列表 |
| 2 | 点「上传照片」，选 `docs/ui-run-materials/alpha_new_shot.jpg` | 提示「录入成功」，下方显示画质指标 |

> 门控 7 条规则的阈值是实测标定的：`backend/scripts/calibrate_quality.py` 可复现。

### M3 · 人脸签到 `/attendance` —— 验证 0.56 阈值与歧义检测

**先关掉后端窗口 A 之前不用做这步**（签到页需要后端在跑）。用现成素材：

| 上传 | 实测相似度 | 界面预期 |
|---|---|---|
| `alpha_enrolled_1793153424000.jpg` | **1.0000** | 「签到成功：<姓名>」，下方显示相似度与签到时间 |
| `alpha_new_shot.jpg` | **0.9786** | 同上（**这是"换一张照片也能认出"的实证**） |
| `stranger_1.jpg` | **0.1142** | 「识别失败」，显示「最高相似度 0.1142，未达阈值 0.56」 |
| `stranger_3.jpg` | **0.2394** | 同上（陌生人里最像的一个，仍远低于阈值） |
| `stranger_7.jpg` | **-0.0039** | 同上 |

再点一次已签到过的照片 → 提示「今日已签到（无需重复签到）」。

> **歧义检测（ambiguous）**：需要「同一人登两个学号」才会触发。演示库里没有这种数据，
> 想看效果：把 `alpha_new_shot.jpg` 也录给另一个学生（如 `20240002`），
> 再签到时 top1 与异人几乎咬平 → `margin < 0.27` → 提示「识别余量偏小」。

> **为什么陌生人相似度这么低（-0.004~0.239）**：库里 alpha 是正面清晰照，
> 陌生人来自远景小脸，本身就是负样本里最难的一类。真人的异人上限实测是 **0.2099**
> （那是「同一批正样本互相比」的更严格口径），这里远景脸连特征都不太稳定。

## 三、跑完怎么收尾

回到那两个 cmd 窗口，各按 **Ctrl+C** 停掉服务即可。

> ⚠️ **不要用 `taskkill /F /IM python.exe`** —— 那是杀掉本机**所有** Python 进程，
> 别的项目、正在跑的脚本会一起陪葬。只停自己起的这两个窗口就够了。

如果要恢复演示数据（M3 播种会重建库）：

```bat
cd /d E:\your\path\to\face-attendance\backend
.venv\Scripts\python.exe scripts\seed_demo.py --drop --students 28 ^
    --faces-from scripts/sample_faces --max-enroll 20
```

## 五、素材清单（`docs/ui-run-materials/`）

| 文件 | 是什么 | 实测行为 |
|---|---|---|
| `alpha_enrolled_*.jpg`（6 张） | alpha 已录入的原图 | 签到成功，相似度 1.0000 |
| `alpha_new_shot.jpg` | **同一人**换了一张（缩放 90% + 调光 + 重编码） | 签到成功，相似度 0.9786 |
| `stranger_1..7.jpg` | 办公室远景里裁出的 7 个**不同的人** | 未识别，相似度 -0.0039~0.2394 |

> ⚠️ **素材不入库**：这些是真实人脸，仓库是公开的，`docs/ui-run-materials/` 已加进 `.gitignore`。
> 素材由脚本现场生成，可复现、不联网：
> ```bat
> cd backend
> .venv\Scripts\python.exe scripts\make_ui_materials.py ^
>     --panorama-dir "D:\你的照片目录"
> ```
> `--panorama-dir` 指向**含多个人的一张照片**所在的目录（脚本按「全景/远景/panorama/office」
> 关键字自动挑），也可直接 `--panorama "D:\照片\办公室远景.png"`。
> 找不到源图时脚本会跳过陌生人素材并明确提示（不影响「认出」路径的测试）。
> 生成后核对每张图的实际行为（跑在临时隔离库里，不碰演示数据）：
> ```bat
> .venv\Scripts\python.exe scripts\verify_ui_materials.py
> ```
