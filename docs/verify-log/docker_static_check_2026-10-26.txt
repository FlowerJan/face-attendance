2) 静态核对查出的问题 ①：构建上下文会把 875MB 的 venv 打进镜像
────────────────────────────────────────────────────────
$ du -sh backend/.venv
> 875M    backend/.venv

原 .dockerignore 里写的是 `.venv` / `venv` —— 在 Docker 的匹配语义中，
不带 `**/` 前缀的模式只作用于上下文根那一层，**漏掉 backend/.venv**。
`COPY backend ./backend` 会把整个 Windows 虚拟环境（含大量 .pyd）拷进镜像。

修复：改为 `**/.venv/` `**/venv/` `**/__pycache__/`，并顺手排除 frontend/。

实测（自写脚本模拟 dockerignore 过滤，非 docker 官方实现，仅用于量化）：
  改动前：保留 21459 个文件 / 671.9 MB
  改动后：保留   307 个文件 /   7.1 MB
  改动后被忽略的目录包含 backend/.venv/（820.7 MB）、backend/models/buffalo_l/（325.5 MB）、
  frontend/（165.9 MB）

【2026-10-28 复跑】tools/check_docker_context.py 之前写成了一段未闭合的文档字符串，
  脚本本身从未真正跑通过（上面的数字是当时手工统计的）。修复后复跑：
  上下文保留 530 个文件 / 32.5 MB
  与 10-26 的 307 / 7.1 MB 有差异，原因是这两天的仓库状态变了，不是过滤规则回退：
    ① 新增了 docs/ 下的标定报告、backend/scripts/checkin_threshold_sweep.py 等文件；
    ② 本机跑过评测与测试，多出 backend/.eval/、backend/attendance.db-wal 等运行产物。
  关键结论不变：backend/.venv（820.7 MB）、backend/models/buffalo_l（325.5 MB）、
  frontend/（165.9 MB）三大块均被正确排除。

3) 静态核对查出的问题 ②：数据卷挂错了路径，业务数据其实没持久化
────────────────────────────────────────────────────────
backend/core/config.py（节选）：
    BASE_DIR: Path = Path(__file__).resolve().parent.parent
    SQLITE_URL: str = f"sqlite:///{BASE_DIR / 'attendance.db'}"
    MILVUS_DB_PATH: str = str(BASE_DIR / "milvus_lite.db")

默认取值实测（venv python）：
> SQLITE_URL      = sqlite:///E:\workbuddy-projects\face-attendance\backend\attendance.db
> MILVUS_DB_PATH  = E:\workbuddy-projects\face-attendance\backend\milvus_lite.db

⇒ 两个库都落在 /app/backend/ 根下，而旧 compose 只挂了 `app-data:/app/backend/data`。
  /app/backend/data 里放的是启动时加载的 班级.csv / 专业.csv 字典（core/enums.py 读取），
  不是业务数据；真挂上去还会把字典遮住。
  净效果：容器一删，考勤记录和向量库全丢 —— 与注释宣称的"持久化"相反。

修复：新增 app-state:/app/backend/state，并用环境变量把两个库指过去。
“不改 Python 代码也能生效”这件事已实测（pydantic-settings 字段名同名环境变量覆盖）：

$ SQLITE_URL=... MILVUS_DB_PATH=... python -c "from core.config import settings; print(...)"
> SQLITE_URL      = sqlite:////tmp/state_test/attendance.db
> MILVUS_DB_PATH  = C:/Users/.../Temp/state_test/milvus_lite.db
  （注：上面这条是 Git Bash 在 Windows 上把 /tmp 自动转成了本机临时目录，
    属于宿主 PATH 转换，不代表容器内行为；容器内 Linux 路径不会被改写。）
> 默认值对照组同上第 2 段。
